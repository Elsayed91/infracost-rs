## TASK 1: CUD Purchase Options

### Purchase Option Values

The Infracost API uses the following purchase_option values for GCP Committed Use Discounts:

1. **1-Year CUD**: `Commit1Yr`
2. **3-Year CUD**: `Commit3Yr`

### Description Pattern

Commitment pricing products use this description pattern:
- `Commitment v1: {FAMILY} Cpu in {LOCATION} for {DURATION}`

Examples:
- `Commitment v1: N2 Cpu in Americas for 1 Year`
- `Commitment v1: N2 Cpu in Americas for 3 Year` (note: not "3 Years" for N2)
- `Commitment v1: N2D AMD Cpu in Americas for 1 Year`
- `Commitment v1: N4 Cpu in Americas for 3 Years`

### Verified Discount Percentages

**N2 Family (us-central1):**
- OnDemand: $0.031611/hour
- 1-Year CUD: $0.019915/hour → **37% discount** ✓
- 3-Year CUD: $0.014225/hour → **55% discount** ✓

**N2D AMD Family (us-central1):**
- OnDemand: $0.027502/hour
- 1-Year CUD: $0.017326/hour → **37% discount** ✓
- 3-Year CUD: $0.012376/hour → **55% discount** ✓

### Regional Consistency

The purchase_option values work consistently across all regions:

| Region | N2 OnDemand | N2 1-Year CUD | N2 3-Year CUD |
|--------|-------------|---------------|---------------|
| us-central1 | $0.031611 | $0.019915 | $0.014225 |
| us-east1 | $0.031611 | $0.019915 | $0.014225 |
| europe-west1 | $0.034773 | $0.021907 | $0.015648 |
| asia-southeast1 | $0.038999 | $0.024567 | $0.017548 |

### Additional Purchase Options

- **OnDemand**: Standard on-demand pricing
- **Preemptible**: Spot/preemptible instances
- **CmtCudPremium**: Committed Use Discount Premium (for custom instances)

## Key Findings and Special Handling

### 1. Universal Query Pattern

For all Compute Engine instances:
```
vendor: gcp
region: <region>
service: Compute Engine
resourceGroup: CPU
```

### 2. Description Patterns by Purchase Type

**OnDemand:**
- Pattern: `{FAMILY} Instance Core running in {LOCATION}`
- Example: `N2 Instance Core running in Americas`

**Custom instances:**
- Pattern: `{FAMILY} Custom Instance Core running in {LOCATION}`
- Example: `N2 Custom Instance Core running in Americas`

**Preemptible/Spot:**
- Pattern: `Spot Preemptible {FAMILY} Instance Core running in {LOCATION}`
- Example: `Spot Preemptible N2 Instance Core running in Americas`

**Committed Use Discounts:**
- Pattern: `Commitment v1: {FAMILY} Cpu in {LOCATION} for {DURATION}`
- Example: `Commitment v1: N2 Cpu in Americas for 1 Year`

**Sole Tenancy:**
- Pattern: `{FAMILY} Sole Tenancy Instance Core running in {LOCATION}`
- Example: `N2 Sole Tenancy Instance Core running in Americas`

### 3. Special Naming Requirements

**N2D AMD and T2D AMD:**
- Must include "AMD" in description
- Commitment: `N2D AMD Cpu` not just `N2D Cpu`

**C2D AMD:**
- Must include "AMD" in description

**ARM instances:**
- T2A: `T2A Arm Instance Core`
- C4A: `C4A Arm Instance Core`

**Memory-optimized:**
- M3: `M3 Memory-optimized Instance Core`
- General memory: `Memory-optimized Instance Core`

### 4. Families Without CUD

**T2A Arm** is the only modern family found without commitment pricing:
- Only OnDemand and Preemptible available
- No Commit1Yr or Commit3Yr options

### 5. Regional Location Mapping

Regions map to location names in descriptions:
- us-central1, us-east1 → "Americas"
- europe-west1 → "EMEA"
- asia-southeast1 → "Singapore"

### 6. Custom Instance Premium

Custom instances have a slight premium over standard:
- N2 Standard: $0.031611
- N2 Custom: $0.03319155 (~5% premium)

### 7. Sole Tenancy Premium

Sole tenancy has an additional premium charge:
- Base price: N2 Instance price
- Premium: `Sole Tenancy Premium for N2 Sole Tenancy Instance Core running in Americas`

## Implementation Recommendations

### 1. Query Structure

For compute instances with CUD support:
```yaml
query:
  vendor: gcp
  region: <region>
  service: Compute Engine
  attributes:
    - key: resourceGroup
      value: CPU
  post_filter:
    description_starts_with: "{FAMILY} Instance Core running"
```

### 2. Purchase Option Filter

To get CUD pricing:
```yaml
price_filter:
  purchase_option: Commit1Yr  # or Commit3Yr
```

### 3. Family Name Handling

Create a mapping function that transforms Terraform family names:
- `n2d` → `N2D AMD`
- `t2d` → `T2D AMD`
- `c2d` → `C2D AMD`
- `t2a` → `T2A Arm`
- `c4a` → `C4A Arm`
- `m3` → `M3 Memory-optimized`
- All others → Uppercase (e.g., `n2` → `N2`, `c3d` → `C3D`)

### 4. Multi-Component Pricing

For instances, you need separate queries:
1. CPU pricing (resourceGroup=CPU)
2. Memory pricing (resourceGroup=Memory) 
3. GPU pricing if applicable (resourceGroup=GPU)

### 5. Commitment Duration Variations

Note the inconsistent naming in descriptions:
- Some use "1 Year" / "3 Year" (singular)
- Some use "1 Year" / "3 Years" (plural)
- Use purchase_option filter instead of description matching

## Query Examples

### Example 1: N2 OnDemand
```bash
irs query -v gcp -r us-central1 \
  --service "Compute Engine" \
  -a 'resourceGroup=CPU' \
  --limit 10 -f json | \
  jq '.[] | select(.attributes[] | select(.key=="description" and .value=="N2 Instance Core running in Americas"))'
```

### Example 2: N2 1-Year CUD
```bash
irs query -v gcp -r us-central1 \
  --service "Compute Engine" \
  -a 'resourceGroup=CPU' \
  --limit 500 -f json | \
  jq '.[] | select(.prices[0].purchase_option == "Commit1Yr") | select(.attributes[] | select(.key=="description" and (.value | contains("N2 Cpu"))))'
```

### Example 3: N4 All Purchase Options
```bash
irs query -v gcp -r us-central1 \
  --service "Compute Engine" \
  -a 'resourceGroup=CPU' \
  --limit 1000 -f json | \
  jq -r '.[] | select((.attributes | map(select(.key == "description")) | .[0].value) | test("N4 .* Americas")) | "\(.prices[0].purchase_option)|\(.attributes | map(select(.key == "description")) | .[0].value)|\(.prices[0].usd)"'
```
